Команды и их назначение



git log --oneline --stat
Показала краткую историю коммитов со статистикой изменений.



git diff HEAD\~2 HEAD -- lab03/calc.py
Показала разницу между версией файла два коммита назад и текущей.



git show HEAD\~1
Показала подробности предпоследнего коммита: автора, дату, изменения.



git log -S"def" --oneline -- lab03/calc.py
Искала коммиты, где в файле появлялась строка с "def". Ничего не нашла.



git blame lab03/calc.py
Показала, кто и в каком коммите добавил каждую строку файла.



Чем отличается git diff от git show и git log

git diff — сравнивает две версии файлов и показывает разницу между ними.


git show — показывает подробности конкретного коммита (кто, когда, что).


git log — показывает список коммитов (историю).



Что нашли команды log -S и blame

log -S ищет коммиты, в которых появлялась или исчезала определённая строка.


blame показывает авторство каждой строки файла.



Восстановление файла



git restore lab03/calc.py
Возвращает файл в рабочей папке к состоянию последнего коммита.
Используется, когда изменения ещё не добавлены в индекс и их надо отменить.



git restore --source=HEAD\~2 lab03/calc.py
Возвращает файл к состоянию из указанного коммита (два назад).
Позволяет посмотреть старую версию и продолжить с ней работу.



Отмена коммита



git revert HEAD создаёт НОВЫЙ коммит, который отменяет изменения

предыдущего. Старый коммит остаётся в истории.



git reset --hard удаляет коммит из истории полностью, переписывая её.

Это опасно, если коммит уже отправлен на GitHub: у других людей

история разойдётся.



revert безопаснее для опубликованной истории, потому что не меняет

прошлое, а только добавляет отменяющий коммит.
